API 接口文档

卡密验证、设备绑定、在线心跳、同行识别、云更新分发与云控配置，统一走同一套 HTTP 接口。

版本 1.7 UTF-8 · JSON POST only 更新 2026-11-09

01概览

极验云服务端对外只暴露 4 个 PHP 端点，所有业务动作通过加密信封里的 action 区分。客户端不需要会话、Cookie 或后台登录，只需要后台创建应用时生成的配置：

配置项说明
app_id应用编号，正整数
developer_username开发者账号（应用所有者用户名）
encrypt_format加密方式 0–8，见「加密与签名」
api_key加密密钥，长度与格式随加密方式变化
sign_type签名方式 0–14
sign_key签名密钥；sign_type=0 时可为空
协议分层：HTTP 传输 → 外层 JSON 信封（四个字段）→ 内层业务参数（加密后的 query 串）→ 业务响应（加密后的 JSON）。每一层都独立校验，错误码也分层返回。

基础地址（两个站点，按客户端类型选择）：

用途基础地址协议
C++ / 原生客户端、卡密、云控http://api.和泉纱雾.cn/api/HTTP
Java / 桌面客户端（可选）https://jiyan.和泉纱雾.cn/api/JiYan/HTTPS

命令行工具不支持中文域名时，用 punycode：api.xn--0try77c6um82w.cn、jiyan.xn--0try77c6um82w.cn。

02快速开始

  1. 在控制台创建应用，记下 app_id、encrypt_format、api_key、sign_type、sign_key。
  2. 客户端初始化时保存上述配置，并生成稳定的 device_id（Android 建议 ANDROID_ID，桌面可用机器码/UUID，持久化保存）。
  3. 先调用 get_crypto_options 自检密钥是否匹配，再调用 use_card 验证卡密；成功后按返回的「心跳间隔秒」定时调用 heartbeat。

最小的请求（加密方式 0，即明文，仅用于联调）：

curl -s http://api.和泉纱雾.cn/api/key.php \
  -H 'Content-Type: application/json' \
  -d '{
    "developer_username": "你的开发者账号",
    "app_id": 12345,
    "iv": "",
    "data": "action=use_card&rc=0123456789abcdef0123456789abcdef&card_key=TEST-0001&device_id=abcdef0123456789"
  }'

加密方式 1 及以上时，data 是加密后的 Base64 串、iv 是 Base64 的 16 字节 IV；签名方式非 0 时还要在内层参数里加 timestamp、nonce、signature_version=2、signature_scope、signature。

03接口端点

端点用途允许的 action
/api/key.php卡密验证、心跳、卡密详情、解绑、公告、加密选项、建卡use_card heartbeat get_card_info unbind_device get_announcement get_crypto_options create_card_client
/api/user.php同行识别：上报玩家身份并返回在线列表update_game_info
/api/Cloudupdate.php云更新：版本检查、清单、取下载地址、下载回执check_version get_update_manifest get_download_url confirm_download
/api/cloud-client.php云控：拉取/上报远程配置（会员功能）sdk_sync

四个端点都只接受 POST。其它方法返回 405；未定义的路径返回 404，都不会进入业务逻辑。

04请求格式

请求头

POST /api/key.php HTTP/1.1
Host: api.和泉纱雾.cn
Content-Type: application/json; charset=utf-8
Content-Length: 512

{ ... }

外层信封

请求体是一个 JSON 对象，固定四个字段：

字段类型必填说明
developer_usernamestring是开发者账号（应用所有者），≤128 字节
app_idint / string是应用编号，正整数
ivstring见加密方式AES 类加密的 Base64 IV（16 字节）；非 AES 方式传空串
datastring是内层参数按加密方式处理后得到的字符串

请求体上限 1 MiB；data 为空或超出上限会被直接拒绝，返回前置错误。

内层参数

内层是 k=v&k=v 形式的 query 串（加密前），所有值都是字符串，服务端按字段名取值：

参数必填说明
action是业务动作，取值见各端点
rc建议请求标识，32 位随机串；响应会在 data.rc 原样回显，用于把响应与请求配对
card_key按接口卡密号码；别名 card card_no key
device_id按接口设备标识；别名 markcode user_mark，≤64 字符（免绑卡可到 128）
user_name按接口玩家名；别名 player_name
user_uid按接口玩家 UID；别名 player_uid
password按应用安全请求密码，仅当应用开启「安全请求校验」时需要
token按应用安全请求 Token，同上
timestampv2 必填10–16 位数字，秒或毫秒；与服务端时间偏差不得超过 300 秒
noncev2 必填16–64 位，字符集 [A-Za-z0-9_-]，一次性，重复即拒
signature_versionv2 必填固定字符串 2
signature_scopev2 必填key（key.php）、user（user.php）、cloud（Cloudupdate.php）、cloud_control（云控）
signaturev2 必填按下面的规范串计算出的签名
同一个请求里不要重复出现同名字段；服务端按出现顺序解析，重复字段会导致取值不确定。

05加密与签名

加密方式

编号名称密钥 / IV
0不加密（明文）—
1AES-256-CBC + PKCS#7api_key 为 Base64 的 32 字节；iv 为 Base64 的 16 字节
2自定义 Base64 编码集api_key 为 64 字符置换表
3极验 EnvProtoapi_key 十六进制
4JiYan-Seal v1（HMAC 密钥流 + 完整性标签）api_key 64 位十六进制
5AES-256-CBC + HMAC-SHA256（Encrypt-then-MAC）api_key Base64 32 字节；iv Base64 16 字节
6AES-256-GCM（AEAD）api_key Base64 32 字节；输出 base64(nonce12‖密文‖tag16)
7ChaCha20-Poly1305（AEAD）api_key Base64 32 字节；输出 base64(nonce12‖密文‖tag16)
8XChaCha20-Poly1305（AEAD）api_key Base64 32 字节；输出 base64(nonce24‖密文‖tag16)
会员专享：加密 5–8（带完整性校验的 AEAD / Encrypt-then-MAC）；其余加密方式免费。

加密结果放在外层 data；明文模式（0）下 data 就是内层 query 串本身。

签名方式

编号算法计算方式
0不签名—
1–11MD5 / SHA512 / CRC32 / SHA256 / RIPEMD160 / SHA1 / SHA224 / SHA384 / SHA3-512 / SHA3-256 / SHA3-224hash(content + sign_key)
12JiYan-Sign（HMAC-SHA256）HMAC-SHA256(key=sign_key, msg=content)
13JiYan-Sign+（双段 HMAC）HMAC(content) + "." + substr(HMAC("jy1"+content+sign_key), 0, 16)
14BLAKE2b-256（带密钥）BLAKE2b-256(content, key=SHA256(sign_key))，输出 64 位小写十六进制
会员专享：签名 13–14（双段 HMAC / 带密钥 BLAKE2b）；其余签名方式免费。

v2 规范串

当 signature_version=2 时，content 按下面的规则拼出（UTF-8 字节）：

jy-req-v2\n
{signature_scope}\n
{app_id}\n
2\n
{len(name)}:{name}={len(value)}:{value}\n   ← 每个参数一行，按 name 字节序升序，排除 signature 本身
  • len() 是 字节长度，不是字符数；中文按 UTF-8 计 3 字节。
  • 参与签名的参数包含 action、rc、timestamp、nonce、signature_version、signature_scope 以及该接口的业务参数；数组/对象类型的值不参与。
  • 先验签、后消费 nonce：验签失败不会占用 nonce。
  • 显式 signature_version=2 才走本规则；不带该字段按历史 v1（按参数出现顺序拼接 value）处理。

响应签名

服务端对响应同样签名，参与内容为：

sign(
  (success ? "true" : "false") + message + json_encode(data),
  sign_type, sign_key
)

比对时必须使用「收到的原始 data 文本」，不能重新序列化后再算（键顺序与转义会变化）。SDK 已内置该逻辑。

06响应格式

业务响应体是加密后的字符串，Content-Type: text/plain; charset=utf-8，需按应用的 encrypt_format 解密后才是 JSON（加密方式 0 时直接就是 JSON）。

{
  "success": true,
  "code": 0,
  "message": "卡密验证成功",
  "data": { "rc": "0123...cdef", "到期时间": "2026-12-31 23:59:59" },
  "signature": "响应签名"
}
字段说明
success业务是否成功。失败时看 code 与 message
code业务码，成功为 0，失败见错误码表
message可直接展示的中文说明
data业务数据；请求带 rc 时一定回显 data.rc
signature响应签名，校验规则见上一节
前置错误：如果请求在解密、查应用、验签之前就失败（例如应用不存在、请求体格式错），响应不是 JSON 而是纯文本，以 JiYan_Error 开头，例如 JiYan_Error应用不存在（历史前缀 (Env-Error) 已废弃，1.7 SDK 不再识别）。客户端应按「前缀 + 文本」兼容，而不是直接 JSON 解析。

07卡密接口 /api/key.php

7.1 验证卡密 action=use_card

校验卡密是否有效、绑定设备、登记在线会话；返回到期时间与在线人数。这是登录流程的入口。

参数必填说明
card_key是卡密号码
device_id是设备唯一标识，绑定后不可跨设备使用
user_name否玩家名，用于后台在线列表展示
user_uid否玩家 UID，用于同行识别与封禁

成功 data

字段说明
到期时间YYYY-MM-DD HH:mm:ss 或字符串 永久
剩余秒剩余可用秒数；永久卡为 -1
在线人数当前窗口内在线设备数
game_uids在线玩家 UID 数组（同游戏）
心跳间隔心跳间隔秒数（客户端按此定时心跳）
心跳间隔秒同上，显式秒字段（推荐使用）
在线判定窗口秒超过该秒数未心跳即视为离线
server_time服务器时间戳（秒）
need_reverify1 表示必须重新验证卡密，不能重试原请求
type卡密类型：1 普通 / 2 多设备

常见失败：2001 卡密不存在 / 2002 卡密已到期 / 2005 卡密已被禁用 / 2006 用户已被封禁 / 1001 机器码为空 / 1005 安全请求密码或 Token 错误。

7.2 心跳 action=heartbeat

定时续期在线状态。间隔按 use_card 返回的「心跳间隔秒」执行，默认 10 秒。

参数必填说明
card_key是卡密号码
device_id是与验证时一致
user_name否玩家名
user_uid否玩家 UID

成功 data：到期时间、剩余秒、在线人数、心跳间隔、心跳间隔秒、在线判定窗口秒、server_time、need_reverify、type。

心跳返回失败（例如 2006 封禁、2002 到期）时，必须停止游戏功能并提示用户，不要继续重试；need_reverify=1 时必须重新走 use_card。

7.3 卡密详情 action=get_card_info

参数：card_key（必填）。返回卡密号码、类型、有效天数/小时/分钟、最大设备数、绑定设备、卡密状态（0 未使用 / 1 使用中 / 2 已到期）、创建时间、到期时间、最后使用时间、禁用状态、是否不检查设备、备注。

7.4 解绑设备 action=unbind_device

参数必填说明
card_key是卡密号码
device_id是当前绑定的设备

成功返回 卡密号码 与 到期时间。会受应用的「解绑冷却时间」「解绑次数上限」「解绑扣时」配置影响：2003 表示冷却未到或次数不足。

7.5 公告 action=get_announcement

无参数。成功返回 announcement 文本；应用关闭公告功能时返回 3003「程序公告功能已关闭」。

7.6 加密选项自检 action=get_crypto_options

无参数。返回该应用当前可用的加密/签名编号、是否会员、会员要求，以及当前配置：

{ "encrypt": [...], "sign": [...], "is_vip": true, "vip_required": true,
  "current": { "encrypt_format": "1", "sign_type": "12" } }

7.7 客户端建卡 action=create_card_client

在客户端直接创建卡密（从开发者的卡密余额扣减）。无需后台登录，但需要应用可用且验签通过。

参数必填说明
card_keys否自定义卡号，多个用空白/逗号分隔（最多 500 个）；不传则随机生成
card_type否1 普通 / 2 多设备（默认 1）
duration_days否有效天数（36500 表示永久）
duration_hours否有效小时
duration_minutes否有效分钟
max_devices否最大设备数，1–10000
notes否备注，≤255 字符

返回：数字下标的卡密数组 + card_balance（扣减后的卡密余额）。单次卡（单次使用类型）暂未开放。

09云更新 /api/Cloudupdate.php

9.1 版本检查 action=check_version

参数必填说明
Name否本机 SO 文件名；别名 file_name
MD5否本机文件摘要；别名 md5
version否本机版本号

返回 need_update（0/1）、has_file、source（local/remote）、file_id、file_name、latest_md5、file_size、version、update_content、download_url。

版本号只要与云端不一致就触发更新（允许回退版本号），不要求单调递增。

9.2 完整清单 action=get_update_manifest

无参数。一次返回全部已加入云更新的文件（不分页，上限 2000 条）：

{
  "file_list": [ { "file_id": 18, "file_name": "libProject.so", "file_size": 23871416,
                   "file_md5": "700db3...8250", "source": "local" } ],
  "latest_version": "3.0",
  "update_content": "本次更新内容",
  "remaining_times": 2999
}

9.3 获取下载地址 action=get_download_url

参数必填说明
file_id是来自清单或版本检查
device_id建议票据与设备绑定，防止链接被别处回执扣次

本地文件返回 download_url（带一次性票据）、ticket、file_name、file_size、file_md5、remaining_times；外链文件直接返回三方地址，不发票据、不扣次。

9.4 下载回执 action=confirm_download

参数必填说明
file_id是文件编号
ticket本地文件必填取地址时返回的票据
device_id建议与取票据时一致
md5_ok是本地 MD5 与清单一致时传 1

返回 confirmed、charged（是否扣次）、source、remaining_times。票据只能成功回执一次，重复回执不会重复扣次。

10云控通道 /api/cloud-client.php

远程下发配置（开关、数值、下拉、按钮），仅会员应用可用。通道复用同一套加密信封，但内层字段固定 15 个，且必须显式 v2 签名。

字段说明
action固定 sdk_sync
app_id必须与外层一致
developer_uid开发者账号，必须与所有者一致
password / token安全请求凭据（应用开启时必填）
card_key / device_id当前登录的卡密与设备
capabilities客户端支持的控件能力，JSON 数组字符串
acks已确认的指令回执，JSON 数组字符串
signature_version固定 2
signature_scope固定 cloud_control
timestamp / nonce / rc时间戳、一次性随机数、请求标识
signaturev2 规范串签名

响应会在 data 中绑定本次 rc、request_nonce、signature_scope、app_id、card_key、device_id，客户端必须逐项比对，不一致直接丢弃。

云控要求应用所有者是会员。非会员返回失败，不会下发任何配置。

11错误码

错误分三层，排查时按顺序看：HTTP 状态码 → 业务码 code → SDK 本地错误。接口正常工作时始终返回 HTTP 200，业务失败是 200 + success=false。

HTTP 状态码

状态码含义常见原因处理建议
200成功—检查 success 与 code
400请求格式错误不是合法 JSON；缺少 developer_username/app_id/iv/data；密文损坏核对请求体字段与加密方式是否与后台一致
401未授权访问了需要后台登录的管理接口，或令牌过期客户端接口不会返回此码，出现即地址写错
403被拒绝无权限、IP 受限、被防火墙或 WAF 拦截检查服务器安全策略
404路径不存在端点写错（例如 /api/key.php 写成 /api/env/key.php）核对基础地址
405方法不允许用了 GET / PUT改为 POST
413请求体过大超过 1 MiB压缩或分文件
429请求过多触发限流退避后重试
500 / 502 / 503 / 504服务端异常PHP 错误、网关超时重试；持续出现联系服务方

业务码

code含义典型 message
0成功成功
1001参数缺失或格式非法机器码不能为空 / user_name / user_uid 不能为空
1004时间戳或 nonce 校验失败请求已过期，请校准本机时间 / 重复请求，请勿重试
1005权限、凭据或白名单不通过安全请求密码错误 / 该接口不允许此操作
1006价格或配置已变化，需要重试价格已更新，请重新确认
2001卡密不存在或参数无效卡密不存在 / 请输入卡密
2002卡密已到期卡密已到期
2003解绑冷却或次数不足解绑失败,换绑时间不足
2005卡密已被禁用卡密已被禁用
2006用户已被封禁用户已被封禁
3001应用已关闭应用已关闭
3003功能未开启程序公告功能已关闭
9999其它业务失败见 message

排查顺序

  1. 用 curl 直接打接口，确认 HTTP 200 且返回可解密（排掉域名、证书、网关）。
  2. 看返回是 JiYan_Error… 还是 JSON：前者说明没进业务（应用编号、加密配置）。
  3. JSON 里 success=false 看 code：1005 多为凭据/白名单，2001/2002/2006 是卡密本身。
  4. 签名失败先核对 sign_type、sign_key 是否与后台一致，再核对规范串（长度用字节、按 name 排序）。
  5. 仍然不通，把 rc、时间、返回原文一起提供给服务方排查。

12心跳与在线

在线状态由「心跳时间戳 + 在线判定窗口」共同决定。两个字段都由服务端下发，客户端不要写死：

字段说明
心跳间隔秒建议的心跳周期（默认 10 秒，可后台调整）
在线判定窗口秒超过该时长未心跳即视为离线（约为间隔的 4 倍，最小 30 秒）
  • 验证成功后立即开始心跳；窗口内至少成功一次才算在线。
  • 心跳失败按错误码处理：2006/2002 停止功能，网络类错误可退避重试。
  • 退出游戏时不必额外调用接口，停止心跳即可在窗口后自动离线。

13限制与建议

项目限制
请求体≤ 1 MiB
云控解密后参数≤ 64 KiB
时间戳偏差±300 秒
nonce16–64 位，一次性
云更新清单≤ 2000 个文件
建卡单次 ≤ 500 张，受卡密余额限制
下载次数按应用流量包扣减，回执成功才扣
  • 心跳周期不要小于 10 秒；在线人数多时优先增大周期，而不是并发重试。
  • 每台设备只保留一个心跳线程；重连时复用同一个 device_id。
  • 下载大文件用 Range 续传，失败从断点继续；不要整包重下。
  • 所有请求都应校验响应签名与 data.rc，防止中间设备篡改或串包。

14SDK 本地错误

以下错误由客户端本地产生，不会出现服务端日志，遇到时优先检查本地配置：

错误文本原因
请求体不能为空未提交任何参数
应用请求参数为空缺少 developer_username / app_id
响应解密失败encrypt_format / api_key 与后台不一致
响应签名校验失败sign_type / sign_key 不一致，或 data 被重新序列化
响应请求标识不匹配data.rc 与本次请求不一致（串包或缓存）
网络连接失败DNS、防火墙、域名或端口不通
接口返回失败（未签名）应用未启用签名，服务端失败响应无法校验，仅作提示
