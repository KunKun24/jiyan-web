API Reference

License-key verification, device binding, heartbeats, peer detection, cloud updates and remote configuration — all through one HTTP API.

v1.7 UTF-8 · JSON POST only Updated 2026-11-09

01Overview

The server exposes four PHP endpoints. The business action is carried inside an encrypted envelope, so clients need no session, cookie or admin login — only the application settings generated in the console:

SettingDescription
app_idApplication ID (positive integer)
developer_usernameDeveloper account that owns the application
encrypt_formatEncryption method 0–8
api_keyEncryption key; format depends on the method
sign_typeSignature method 0–14
sign_keySignature key; may be empty when sign_type=0
Layers: HTTP → outer JSON envelope (four fields) → inner parameters (encrypted query string) → encrypted JSON response. Each layer is validated separately and reports its own errors.

Base URLs

Use caseBase URLScheme
Native clients (C++), license keys, remote confighttp://api.和泉纱雾.cn/api/HTTP
Java / desktop clients (optional)https://jiyan.和泉纱雾.cn/api/JiYan/HTTPS

When a tool cannot handle internationalized domains, use punycode: api.xn--0try77c6um82w.cn and jiyan.xn--0try77c6um82w.cn.

02Quick start

  1. Create an application in the console and note app_id, encrypt_format, api_key, sign_type and sign_key.
  2. Persist a stable device_id on the client (Android: ANDROID_ID; desktop: machine ID or a stored UUID).
  3. Call get_crypto_options to self-check the keys, then use_card to verify a key. After success, send heartbeat every “心跳间隔秒” seconds returned by the server.

Minimal request (encryption 0 / plaintext, for local debugging only):

curl -s http://api.和泉纱雾.cn/api/key.php \
  -H 'Content-Type: application/json' \
  -d '{
    "developer_username": "your-developer-username",
    "app_id": 12345,
    "iv": "",
    "data": "action=use_card&rc=0123456789abcdef0123456789abcdef&card_key=TEST-0001&device_id=abcdef0123456789"
  }'

With encryption 1+, data is Base64 ciphertext and iv is a Base64 16-byte IV. With signature 1+, the inner parameters must also carry timestamp, nonce, signature_version=2, signature_scope and signature.

04Request format

Headers

POST /api/key.php HTTP/1.1
Host: api.和泉纱雾.cn
Content-Type: application/json; charset=utf-8
Content-Length: 512

Outer envelope

FieldTypeRequiredDescription
developer_usernamestringyesDeveloper account (owner), ≤128 bytes
app_idint / stringyesApplication ID
ivstringdependsBase64 16-byte IV for AES modes; empty otherwise

Body limit: 1 MiB. Empty or oversized data is rejected before any business logic runs.

Inner parameters

A query string (k=v&k=v) before encryption. All values are strings:

NameRequiredDescription

rcrecommended32-char request id; echoed back as data.rc so responses can be matched
card_keyper actionLicense key; aliases card card_no key
device_idper actionDevice id; aliases markcode user_mark, ≤64 chars (128 for no-bind cards)
user_nameper actionPlayer name; alias player_name
user_uidper actionPlayer UID; alias player_uid
passwordper appRequest password, when the app enables the security check
tokenper appRequest token, same condition
timestampv210–16 digits, seconds or milliseconds; ±300 s skew allowed
noncev216–64 chars from [A-Za-z0-9_-], single use
signature_versionv2Always 2
signature_scopev2key, user, cloud or cloud_control
signaturev2Signature over the canonical string

05Encryption & signature

Encryption

#MethodKey / IV
0None (plaintext)—
1AES-256-CBC + PKCS#7api_key: Base64 32 bytes; iv: Base64 16 bytes
2Custom Base64 alphabetapi_key: 64-char alphabet
3EnvProtoapi_key: hex
4JiYan-Seal v1 (HMAC keystream + tag)api_key: 64 hex chars
5AES-256-CBC + HMAC-SHA256 (encrypt-then-MAC)api_key Base64 32 bytes; iv Base64 16 bytes
6AES-256-GCM (AEAD)api_key Base64 32 bytes; output base64(nonce12‖ct‖tag16)
7ChaCha20-Poly1305 (AEAD)api_key Base64 32 bytes; output base64(nonce12‖ct‖tag16)
8XChaCha20-Poly1305 (AEAD)api_key Base64 32 bytes; output base64(nonce24‖ct‖tag16)
Members only: encryption 5–8 (authenticated AEAD / encrypt-then-MAC). All other modes are free.

In plaintext mode the data field is the raw query string.

Signature

#AlgorithmFormula
0None—
1–11MD5 / SHA512 / CRC32 / SHA256 / RIPEMD160 / SHA1 / SHA224 / SHA384 / SHA3-512 / SHA3-256 / SHA3-224hash(content + sign_key)
12JiYan-Sign (HMAC-SHA256)HMAC-SHA256(key=sign_key, msg=content)
13JiYan-Sign+ (dual HMAC)HMAC(content) + "." + substr(HMAC("jy1"+content+sign_key), 0, 16)
14BLAKE2b-256 (keyed)BLAKE2b-256(content, key=SHA256(sign_key)), 64 lowercase hex
Members only: signature 13–14 (dual HMAC / keyed BLAKE2b). All other modes are free.

v2 canonical string

jy-req-v2\n
{scope}\n
{app_id}\n
2\n
{len(name)}:{name}={len(value)}:{value}\n   ← one line per param, sorted by name bytes, signature excluded
  • len() is the byte length (UTF-8), not the character count.
  • Includes action, rc, timestamp, nonce, signature_version, signature_scope and all business parameters; arrays/objects are excluded.
  • The nonce is consumed only after a successful signature check.
  • Legacy v1 (values concatenated in insertion order) is used when signature_version is absent.

Response signature

sign(
  (success ? "true" : "false") + message + json_encode(data),
  sign_type, sign_key
)

Verify against the raw data text as received; re-serializing changes key order and escaping. The official SDKs already do this.

06Response format

The body is encrypted with Content-Type: text/plain; charset=utf-8 and must be decrypted with the app's encrypt_format (mode 0 returns plain JSON).

{
  "success": true,
  "code": 0,
  "message": "卡密验证成功",
  "data": { "rc": "0123...cdef", "到期时间": "2026-12-31 23:59:59" },
  "signature": "..."
}
FieldDescription
successBusiness result; on failure read code and message
codeBusiness code, 0 = success
messageHuman-readable reason (Chinese)
dataPayload; echoes rc when provided
signatureResponse signature
Pre-flight errors are plain text starting with JiYan_Error, e.g. JiYan_Error应用不存在 (the legacy (Env-Error) prefix is deprecated and no longer recognised by 1.7 SDKs). Parse defensively instead of JSON-decoding blindly.

07License keys /api/key.php

7.1 Verify a key action=use_card

ParameterRequiredDescription
card_keyyesLicense key
device_idyesDevice identifier; bound on first use
user_namenoPlayer name for the online list
user_uidnoPlayer UID for peer detection and bans

data: 到期时间 (expiry or “永久”), 剩余秒 (-1 for permanent), 在线人数, game_uids, 心跳间隔秒, 在线判定窗口秒, server_time, need_reverify, type.

Common failures: 2001 not found, 2002 expired, 2005 disabled, 2006 banned, 1001 missing device id, 1005 wrong request password/token.

7.2 Heartbeat action=heartbeat

Parameters: card_key, device_id (required), user_name, user_uid. Returns the same expiry/online fields as use_card. On 2006/2002 stop the feature; on need_reverify=1 run use_card again.

7.3 Key info action=get_card_info

Parameter: card_key. Returns key number, type, validity, max devices, bound device, status (0 unused / 1 in use / 2 expired), timestamps, disabled flag and note.

7.4 Unbind device action=unbind_device

Parameters: card_key, device_id. Returns 卡密号码 and 到期时间. Subject to the app's cooldown, attempt limit and time deduction; 2003 means cooldown or limit not met.

7.5 Announcement action=get_announcement

No parameters. Returns announcement; if disabled, 3003.

7.6 Crypto options action=get_crypto_options

No parameters. Returns available methods, membership flags and the app's current settings.

7.7 Create keys from the client action=create_card_client

ParameterRequiredDescription
card_keysnoCustom keys separated by spaces/commas (≤500); random when omitted
card_typeno1 normal / 2 multi-device
duration_days / duration_hours / duration_minutesnoValidity (36500 days = permanent)
max_devicesno1–10000
notesno≤255 chars

Returns an array of created keys plus card_balance after deduction. Single-use keys are not available yet.

08Peer detection /api/user.php

8.1 Report player identity action=update_game_info

Parameters: card_key, device_id, user_name, user_uid (all required). Returns 在线人数, game_uids, online_list (≤200), is_peer, heartbeat interval, window and server_time.

09Cloud updates /api/Cloudupdate.php

9.1 Version check action=check_version

Optional parameters: Name (file_name), MD5 (md5), version. Returns need_update, has_file, source, file_id, file_name, latest_md5, file_size, version, update_content, download_url.

Any difference in version string triggers an update — downgrades are allowed too.

9.2 Manifest action=get_update_manifest

No parameters. Returns all files marked for cloud update (≤2000) plus latest_version, update_content and remaining_times.

9.3 Download URL action=get_download_url

Parameters: file_id (required), device_id (recommended, ticket binding). Local files return a one-time ticket URL plus size/MD5; remote files return the third-party URL with no ticket and no quota deduction.

9.4 Download receipt action=confirm_download

Parameters: file_id, ticket (local files), device_id, md5_ok=1. Deducts quota once per ticket; repeated receipts are idempotent.

10Remote configuration /api/cloud-client.php

Members only. Same encrypted envelope, but exactly 15 inner fields and mandatory v2 signature with scope cloud_control. The response binds rc, request_nonce, signature_scope, app_id, card_key and device_id; verify every one before applying commands.

12Heartbeat & online

Online state is derived from the heartbeat timestamp and an online window; both are returned by the server — do not hard-code them.

  • 心跳间隔秒: recommended heartbeat period (default 10 s).
  • 在线判定窗口秒: no heartbeat within this window ⇒ offline (about 4× the interval, minimum 30 s).
  • Start heartbeats right after use_card; stop them on exit and the session expires automatically.

13Limits & tips

ItemLimit
Request body≤ 1 MiB
Decrypted remote-config payload≤ 64 KiB
Timestamp skew±300 s
Nonce16–64 chars, single use
Cloud manifest≤ 2000 files
Key creation≤ 500 per call, limited by balance
  • Keep heartbeats ≥10 s; scale by increasing the period, not by retrying aggressively.
  • One heartbeat thread per device; reuse the same device_id after reconnects.
  • Use Range requests to resume large downloads.
  • Always verify the response signature and data.rc.
